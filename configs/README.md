# 실험 기록 양식

`main`을 처음 실행하면 `configs/experiments_template.csv`를 `data/experiments.csv`로 복사한다. 기존에 작성한 9열 CSV도 사용할 수 있다. 원본 영상은 `data/videos/`에 둔다.

| 열 | 입력 |
|---|---|
| `video_id`, `subject_id` | 영상 고유 코드, 참가자 코드 |
| `distance_m`, `trial` | 거리(m), 반복 번호 |
| `video_file` | `data/videos/` 안의 파일 이름 또는 경로 |
| `start_s`, `end_s` | 영상 시작을 0초로 본 분석 구간. 빈칸은 각각 0과 영상 끝 |
| `gt_bpm` | 같은 분석 구간에서 읽은 스마트워치 BPM의 평균. 기준값을 기록하지 못했다면 빈칸 |
| `notes` | 조명, 자세, 노출, 영상·워치 시각 정렬 방법 등 |
| `watch_file` | 선택 항목. 시간별 워치값 CSV의 경로 또는 `data/watch/` 안의 파일 이름 |
| `watch_offset_s` | 선택 항목. 워치 CSV의 시각에 더해 영상 시작 기준 초로 환산하는 값. 빈칸은 0초 |

촬영할 때 영상 시작 시각과 워치 기록의 기준 시각을 남긴다. 워치값의 갱신·평균 지연을 처리하는 기준은 실험 전에 정하고 `notes`에 기록한다. 스마트워치는 같은 구간의 평균 BPM을 비교하기 위한 기준이다.

시간별 워치 기록을 사용하는 경우 파일의 열 이름은 `time_s,bpm`이다. `gt_bpm`이 비어 있으면 MATLAB이 `time_s + watch_offset_s`가 분석 구간에 들어오는 유효 BPM 표본의 산술 평균을 구한다. 예를 들어 워치 기록을 영상보다 2초 먼저 시작했다면 워치의 2초가 영상의 0초이므로 오프셋은 `-2`다. 실제 지연을 보정했다면 그 값과 근거를 함께 기록한다. 직접 입력한 양수 `gt_bpm`이 있으면 그 값을 사용한다.

실패한 영상과 워치값이 없는 영상도 줄을 유지한다. 결과 CSV는 추정 실패와 기준값 부족을 각각 기록한다. 초 단위 분석 구간이 바뀌면 비교 기준 BPM도 해당 구간에 맞춰 다시 계산한다.
