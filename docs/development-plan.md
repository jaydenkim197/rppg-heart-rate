# RGB 영상 기반 비접촉 심박 추정 개발 계획

## 1. 목표와 현재 단계

스마트폰 얼굴 영상에서 피부 반사광의 변화를 분석하여 한 사람의 심박수를 추정한다. 기본 기능을 만든 뒤 영상처리 방법과 촬영 거리에 따른 정확도와 실패 원인을 비교한다.

현재는 MATLAB 기준 개발 방향과 파일 구조를 정리한 단계다. 초기 실행 파일은 환경 확인을 수행한다. 심박 추정 알고리즘과 실제 영상 검증은 다음 개발 단계다.

## 2. 개발 환경

MATLAB을 사용해 영상 입력, 신호 처리, FFT와 그래프 출력을 연결한다. 기존 디지털영상처리 실습 경험을 활용하고, 각 단계의 배열과 그래프를 확인하며 개발한다.

| 기능 | 사용할 도구 |
|---|---|
| 영상 읽기 | MATLAB `VideoReader` |
| 수동 ROI 선택과 미디언 필터 | Image Processing Toolbox |
| 대역통과 필터 | Signal Processing Toolbox `bandpass` |
| FFT와 기본 그래프 | MATLAB `fft`, `plot` |
| 결과 저장 | MATLAB 표와 CSV 출력 |

팀원의 MATLAB과 툴박스 환경을 확인한다. 얼굴 영역을 추적할 구체적인 방법과 추가 도구는 초기 영상에서 동작을 검토해 선택한다.

## 3. 기본 처리 순서

1. 스마트폰 영상을 불러오고 프레임 시각을 확인한다. 권장 촬영 조건은 1080p, 30 fps, 60초다.
2. 이마와 양쪽 볼의 피부 영역을 정한다. 눈·입·머리카락의 영향을 줄이고 같은 피부 영역을 유지한다. 고정 ROI를 쓰는 초기 실험에서는 얼굴 움직임을 통제하고, 평가용 구현에서는 ROI 유지와 실패 검출을 확인한다.
3. 매 프레임의 피부 영역에서 R·G·B 평균을 구해 시간 순서로 저장한다. ROI 추적 결과는 모든 방법에서 재사용한다.
4. 영상의 실제 시간 간격을 확인하고, 필요한 경우 일정 간격으로 재표본화한다. 0.7~3.0 Hz 대역통과 필터를 적용한다.
5. FFT를 적용해 같은 대역에서 가장 강한 피크 주파수를 찾는다. BPM은 해당 주파수에 60을 곱해 계산한다.
6. 같은 시간 구간의 스마트워치 BPM과 비교하고 성공 여부와 오차를 기록한다.

## 4. 비교할 처리 방법

| 방법 | 초기 구현안 | 검증 목적 |
|---|---|---|
| A | 공통 ROI의 Green 평균 + bandpass + FFT | 기본 성능 확보 |
| B | 각 프레임의 RGB 채널에 3×3 미디언 필터 적용 후 A | 공간 잡음 제거가 심박 오차에 미치는 영향 |
| C | ROI 평균에서 G/(R+G+B)를 계산한 뒤 bandpass + FFT | 공통 밝기 변화의 영향을 줄이는 색상 정규화의 효과 |
| D | 이마·양쪽 볼 각각의 POS 신호와 BPM을 구하고 품질에 따른 가중치로 결합 | 잡음이 큰 부위의 영향 감소 |

B의 필터는 RGB 채널별로 적용하고 경계 처리를 통일한다. C의 분모가 0이거나 유효 신호가 없으면 실패를 기록한다. 프레임별 강한 대조비 보정이 시간 신호를 왜곡할 수 있으므로, 처리 전후 파형과 최종 오차를 함께 확인한다.

D에서는 심박 피크 주변 에너지가 탐색 대역 전체 에너지에서 차지하는 비율을 신호 품질의 초기 후보로 검토한다. 부위별 BPM을 품질 점수로 가중 평균하는 방법과 공통 ROI의 기본 POS 결과를 비교한다. 피크 주변 범위, 유효성 기준, 신호가 없는 경우의 처리 규칙은 초기 검토 자료로 정하고 평가 전에 고정한다. 가중치 총합이 0이거나 필요한 ROI를 확보하지 못하면 실패를 기록한다. 실제 개선 여부는 실험으로 확인한다.

모든 방법은 같은 영상, ROI 집합, 시간 구간, 심박 탐색 범위를 사용한다. D의 영역 구분도 이 공통 ROI 집합 안에서 수행한다. 평가에 사용할 스마트워치 정답을 보고 방법별 설정을 조정하지 않는다.

## 5. 개발 구조

`main.m`에서 공통 설정을 읽고 영상 입력, 방법 선택, BPM 계산, 평가를 연결한다. [시스템 구조](architecture.md)에 각 함수의 입출력과 배열 크기를 정리했다.

| 파일 | 담당 기능 |
|---|---|
| `matlab/main.m` | 실행 진입점과 환경 확인 |
| `matlab/config.m` | 공통 경로와 설정 |
| `matlab/extract_rgb.m` | 영상 읽기, ROI 유지, 원본·공간 필터 RGB 추출 |
| `matlab/apply_method.m` | 방법 A~D의 시간 신호 생성 |
| `matlab/estimate_hr.m` | 필터링, FFT, BPM과 처리 상태 계산 |
| `matlab/evaluate_results.m` | GT 비교, 오차 집계와 결과 출력 |
| `configs/experiments_template.csv` | 빈 실험 기록 양식 |

## 6. 구현 순서와 완료 기준

1. 1 m 영상 하나로 방법 A의 RGB 신호, 처리 후 신호, FFT와 BPM 출력을 확인한다.
2. 방법 B와 C를 추가하고 같은 영상에서 A와 비교한다.
3. 기본 POS를 구현하고 D의 부위별 품질 반영을 추가한다.
4. 모든 방법을 같은 실행 흐름으로 연결하고 결측·추적 실패·신호 부족 상태를 기록한다.
5. 거리별 실험을 수행한 뒤 방법별·거리별 오차와 실패 원인을 분석한다.

팀 회의록의 내부 목표는 11월 27일 오전 9시 전 기능 통합, 오전 9시부터 평가 실험 시작이다. 11월 25일 제안 발표에는 계획과 현재 구현 상태를 설명한다. 12월 12일 최종 발표에는 분석 결과, 데모와 보고서를 준비한다.

## 7. 실험과 평가

스마트폰 후면 카메라와 삼각대를 사용한다. 0.5, 1, 2, 3, 4, 5 m에서 촬영하며 조명과 자세를 통제한다. 3명, 거리별 3회 반복으로 총 54개 영상을 목표로 한다.

스마트워치 심박은 동시에 기록한다. 평균 및 갱신 지연을 고려해 영상과 같은 시간 구간의 값을 비교한다. 실험 기록에는 영상 번호, 참가자 코드, 거리, 반복 번호, 평가 구간, GT BPM과 촬영 조건을 저장한다.

성공한 시도에서 MAE와 RMSE를 구하고 비교에 사용한 시도 수를 표시한다. 전체 촬영 시도의 유효 추정 비율과 실패 원인을 함께 보고한다. GT가 없는 시도는 누락 사유를 기록한다. 실패한 영상의 행을 결과표에 남긴다.

필수 그래프는 원본 RGB 신호, 처리 후 신호, FFT 스펙트럼, 방법별·거리별 오차다. GT/예측 결과 CSV와 실행 방법을 최종 제출 자료에 포함한다. 얼굴 영상과 개별 심박 기록은 참여자의 동의를 받은 방식으로 보관하고 공유한다.

## 8. 협업과 검증

개발 담당자는 공통 설정과 함수 연결을 정리한다. 팀원들은 함수의 입출력 약속에 따라 구현하고, 평가 담당자는 개발 내용과 과제 요구를 바탕으로 평가 시나리오를 구체화한다.

기능 브랜치에 개발 문서와 초기 MATLAB 파일을 커밋하고 PR로 공유한다. AI는 개념 이해, 구현 방향 검토와 코드 초안 작성에 활용한다. 각 단계의 코드와 결과는 팀원이 실제 실행해 확인하고 설명할 수 있도록 검증한다.

현재 확인한 범위는 파일 구성, 문서 연결, 공통 설정과 기록 양식의 일관성이다. 이 작성 환경에는 MATLAB이 없어 MATLAB 실행 검증은 남아 있다. 아직 실제 얼굴 영상의 성능을 측정하지 않았다.
