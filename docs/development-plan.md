# RGB 영상 기반 비접촉 심박 추정 개발 계획

## 1. 목표

스마트폰 얼굴 영상에서 피부 반사광 변화를 분석하여 한 사람의 평균 심박수를 추정한다. 팀 발표 PPT 3~5쪽과 발표자 노트, 과제 안내 3~7쪽을 바탕으로 동일한 영상에서 A~D를 비교하고 거리에 따른 오차와 추정 실패를 기록한다.

## 2. 개발 환경

MATLAB R2022b 이상에서 `VideoReader`로 영상을 읽는다. 얼굴 검출과 KLT에는 Computer Vision Toolbox, 피부 마스크와 미디언 필터에는 Image Processing Toolbox, 대역통과에는 Signal Processing Toolbox를 사용한다. FFT, 입력·출력 표, 그래프는 MATLAB에서 처리한다.

## 3. 기본 처리 순서

1. 영상 파일을 읽고 프레임 시각을 초 단위로 기록한다.
2. 이마와 양쪽 볼에서 피부 영역을 잡은 뒤 KLT로 같은 부위를 추적한다.
3. 매 프레임의 피부 영역에서 R·G·B 평균을 계산한다. 같은 영역에 있는 Green 픽셀을 3×3 미디언 필터로 처리한 뒤 방법 B용 평균도 구한다.
4. 프레임 간격의 중앙값을 표본 간격으로 정하고 일정한 시간 간격으로 선형 보간한다. A~D는 같은 분석 구간을 사용한다.
5. 각 방법의 시간 신호에 0.7~3.0 Hz Butterworth 대역통과를 적용한다. `filtfilt`로 앞뒤 방향을 필터링하고, Hann 창을 적용한 FFT에서 대역 안의 최대 피크를 찾는다. 주파수에 60을 곱하면 BPM이다.
6. 같은 시간 구간의 스마트워치 BPM과 비교한다.

### 3.1 피부 영역 추적

- 정면 얼굴 한 명을 촬영하므로 사전 학습된 `vision.CascadeObjectDetector('FrontalFaceCART')`로 첫 측정 영역을 자동 설정한다. 얼굴 박스의 상대 좌표에서 이마와 양쪽 볼을 지정한다.
- 얼굴 영역에서 특징점을 골라 `vision.PointTracker`의 KLT로 추적한다. 일치한 점으로 `estgeotform2d`의 유사 변환을 구하고 ROI의 꼭짓점에 적용한다. 이동·회전과 크기 변화를 함께 반영하면 얼굴이 조금 움직일 때 머리카락이나 배경이 섞여 생기는 색상 변화를 줄일 수 있다.
- 추적이 끊긴 프레임은 유효하지 않다고 기록한다. 얼굴을 다시 검출할 때 이전 얼굴 박스와 겹치는 후보에서 추적을 재개한다. 영상 시작 시 얼굴을 찾지 못하면 다음 프레임들에서 다시 검출한다. 얼굴 가림, 큰 회전, 먼 거리의 작은 얼굴은 실패 요인이 될 수 있다.
- 피부 영역의 위치와 픽셀 개수는 모든 방법이 공유한다. 1 m 영상에서는 `tracked_roi.png`로 이마와 양쪽 볼 위치를 먼저 확인한다.

정면 검출과 KLT 추적의 구현 근거는 다음 자료를 참고했다.

- [MathWorks 정면 얼굴 검출기](https://www.mathworks.com/help/vision/ref/vision.cascadeobjectdetector-system-object.html)
- [MathWorks KLT 얼굴 추적 예제](https://www.mathworks.com/help/vision/ug/face-detection-and-tracking-using-the-klt-algorithm.html)

## 4. 비교할 처리 방법과 선정 근거

| 방법 | 구현 | 선정 근거 |
|---|---|---|
| A | 공통 ROI의 Green 평균, 대역통과, FFT | 과제 안내 5쪽 기본 방법 |
| B | Green 영상의 3×3 미디언 필터, ROI Green 평균, A와 같은 대역통과와 FFT | 튀는 픽셀을 줄이는 공간 처리 효과를 A와 비교. 3×3은 작은 이웃을 쓰는 초기 조건 |
| C | 공통 ROI에서 G/(R+G+B), A와 같은 대역통과와 FFT | 세 채널에 같은 배율로 생기는 밝기 변화의 영향을 줄이는 색상 비율 실험 |
| D | 부위별 POS, 대역통과와 FFT, 품질 가중 평균 | 상태가 좋은 부위의 추정 BPM에 더 큰 비중 부여 |
| POS | 공통 ROI의 RGB 평균에 기본 POS 적용 | D의 부위별 결합이 기본 POS 대비 오차를 줄이는지 비교 |

POS는 약 1.6초의 RGB 구간을 채널별 평균으로 나눈 뒤 `G-B`와 `-2R+G+B`로 투영한다. 두 투영의 표준편차 비율로 크기를 맞춰 합치고 평균을 뺀 파형을 겹쳐 더한다. B~D의 효과는 실제로 스마트워치와 비교해서 판단한다. C는 색 채널마다 다른 조명 변화에는 영향을 받을 수 있고, D는 움직임으로 생긴 강한 피크에도 높은 품질 점수를 줄 수 있다. 원본·처리 후 파형과 FFT를 함께 확인한다.

- [MATLAB medfilt2](https://www.mathworks.com/help/images/ref/medfilt2.html)
- [MATLAB 양방향 필터링](https://www.mathworks.com/help/signal/ref/filtfilt.html)
- [Wang 외, Algorithmic Principles of Remote PPG, IEEE TBME, 2017](https://doi.org/10.1109/TBME.2016.2609282)

## 5. 품질 판정과 거리 평가

`config.m`의 초기 기준으로 영상 구간은 최소 10초, 추적 유효 프레임은 90% 이상이다. 내부 유효 표본 간 공백이 0.5초를 넘거나 구간의 시작·끝에서 0.25초를 넘게 놓치면 분석 실패로 기록한다. 조건을 만족하는 짧은 내부 공백은 선형으로 잇고, 양 끝은 가까운 유효 표본을 사용한다. 원본 RGB 그래프에는 추적을 잃은 부분을 공백으로 남긴다.

FFT 품질 점수는 최대 피크 주변 ±0.15 Hz의 에너지를 0.7~3.0 Hz 대역 에너지로 나눈 값이다. 모든 방법에 0.25의 초기 기준을 적용한다. D에서는 이 기준을 통과한 부위의 BPM을 구하고 점수 합으로 정규화한 가중치로 평균한다. 이 수치들은 팀의 초기 선택값이다. 초기 영상으로 확인한 뒤 본 실험 전에 고정하고, 평가용 스마트워치 값에 맞춰 조정하지 않는다.

0.5, 1, 2, 3, 4, 5 m에서 촬영하고 같은 시각 구간의 스마트워치 BPM으로 MAE와 RMSE를 계산한다. 전체 촬영 시도를 분모로 유효 추정률을 구하고 실패 원인과 건수를 남긴다. 양쪽 모두 비교 가능한 공통 영상에서 방법을 바꿨을 때 MAE가 얼마나 달라지는지도 기록한다.

## 6. 검증 및 제출

- 72 BPM 합성 신호로 A~D와 POS의 추정 결과, 짧고 긴 공백 처리, 평탄한 신호 실패를 확인한다.
- 실제 1 m 영상에서 이마와 볼을 추적하는지, 처리 전후 파형과 FFT가 예상대로 나오는지 팀이 확인한다.
- 거리별 실험 후 원본 RGB, 처리 신호, FFT, 방법별·거리별 그래프와 원인 분석을 최종 발표와 보고서에 싣는다. 일치하지 않는 사례도 결과로 남긴다.
- 코드는 [시스템 구조](architecture.md), 실제 실행과 결과 파일은 [README](../README.md)에 정리했다. AI 활용과 팀의 검증 과정은 최종 보고서에 기록한다.
