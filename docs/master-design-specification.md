# 통합 설계 명세서 (Master Design Specification)

- 기준일 2026-11-26 KST
- 승인된 근거 [기술 결정 검토서](decision-review.md), 과제 안내 3~11쪽, 최신 후속 지시
- 상태 `DECISION` (확정 방향), `PROPOSAL` (실험 후보와 계약 확장), 구현 상태는 [아키텍처](architecture.md) 및 [개발 계획](development-plan.md)에서 관리한다.
- 교수님 요구사항을 우선한다. 기존 후보, 예비 수치, 팀원 코드와 대조한 기록은 원본 검토서와 Git 이력에 보존한다.

## 1. 목표와 공통 비교 규칙

단일 인물의 동일 피부 영역을 유지하고 RGB 시계열에서 BPM을 추정한다. 이마·왼쪽 볼·오른쪽 볼의 좌표, 픽셀 수, 관측 유효성과 시각을 기록한다. 최종 필수 결과는 A~D, 0.5/1/2/3/4/5 m, 같은 60초 구간의 스마트워치와 비교, MAE·RMSE·유효 추정률·실패 분석, RGB·처리 신호·FFT·방법별·거리별 그래프 및 GT/추정 CSV다.

| 방법 | 제공할 기준과 비교 |
|---|---|
| A | 유효 피부 ROI의 픽셀 수 가중 Green → 공통 Bandpass → 1D FFT → 피크 주파수 × 60. 초기 탐색 대역 0.7–3.0 Hz. 필터 미적용은 연구용 대조군으로 개별 표시한다. |
| B | 공통 ROI의 공간 필터 후 A와 동일한 시간 처리. 미디언 3×3은 초기 후보다. Mean, Gaussian, Bilateral, Adaptive Wiener와 비교한다. |
| C | 같은 공통 ROI에 색상·밝기 처리 후 공통 시간 처리. RGB Sum, 시간 정규화, 색차, Log Chromaticity, HSV 채도를 비교하고 Green은 대조군이다. |
| D | 부위별 POS와 품질 기반 ROI 결합. pooled RGB의 기본 POS를 대조군으로 두고 부위별 단순·품질 가중 평균, Best, Consensus, Spectral Fusion을 비교한다. |

A~D 비교는 기본 ROI 집합, 영상·시간 구간, 시간축 처리 및 탐색 대역을 고정한다. B·C를 A에 독립 적용한다. D의 부위별 품질 제외와 공통 기하·관측 유효성을 구분해 기록한다. D의 가림 대응은 A~D 공통 사례 평가에 더해 따로 보고한다. GT로 FFT 피크를 선택하지 않는다.

## 2. 수집과 기준 장비

[촬영·데이터 수집 프로토콜](experiment-protocol.md)에 카메라·코덱·SSD·시각·기준 장비 검증 절차 및 수집 스키마를 두었다. 4K·60 fps 및 1/60초가 우선 조건이며 고정 노출·WB, 기존 실내조명, 같은 후면 렌즈와 삼각대를 사용한다. 3개 예비, 54개 안정 거리별, 9개 움직임, 9개 회복은 계획 수량이다. 본 실험의 설정은 예비 장비 검증 후 기록한다.

Apple Watch는 공식 거리별 절대 BPM 비교에 사용한다. MAX30102+ESP32는 연속 맥파 및 변화 추적 기준으로 추가하며, 100 Hz는 센서 출력률 확인 전 초기 설정이다. 영상과 ESP32는 시작·종료 LED 이벤트로 정렬한다. 참조 데이터의 질·누락·실제 간격·장비 지연을 기록한다. 측정 부위, 장비 시계와 알고리즘의 지연을 구분한다. ECG 또는 의료 성능과 동등하다는 평가는 별도 검증이 필요하다.

## 3. 공통 데이터 계약

기존 함수와 실험 CSV의 이름을 유지한다. 영상의 분석 구간은 `[start_s,end_s)`이고 시간은 영상 기준 초, 주파수는 Hz, 심박은 BPM, 거리는 m이다. 센서 원시 자료의 타임스탬프 단위는 마이크로초, 시계 동기화 상태는 별도 메타데이터로 기록한다.

| 단계 | 입력·출력 |
|---|---|
| 입력·추출 | `extract_rgb(video_file,settings)` → `time_s` N×1, `raw_rgb` N×3×3(프레임·RGB·ROI), `pixel_counts` N×3, `roi_positions`, `valid` N×1. ROI별 상태 `roi_valid` N×3을 추가할 수 있다. 관측하지 않은 픽셀을 제외하고 이유를 기록한다. B의 `median_rgb`는 필요 시 계산하며 본 MVP에서는 비어 있다. |
| 신호 생성 | `apply_method(rgb_data,method,settings)` → 공통 `time_s`, `values` N×K, `labels`, `method`. A~C와 pooled POS에는 한 열, D에는 ROI별 열을 사용한다. 픽셀 수 0과 NaN/Inf 입력의 범위는 진단한다. |
| 추정 | `estimate_hr(method_signal,settings)` → `predicted_bpm`, `status`, `failure_reason`, `quality`, 실제 분석 시각, 처리 신호와 주파수·파워. 불연속 관측 및 SQI 실패는 신규 유효 결과를 생성하지 않는다. 윈도우별 평가에는 분석 시작·끝, 출력 시각과 과거값 보유 상태를 추가한다. |
| 평가 | `evaluate_results(predictions,ground_truth,settings)` → 시도 ID·평가 구간별 결과를 연결하고 MAE/RMSE와 유효률, 참조 누락·실패 사유를 기록한다. 레거시 CSV의 `gt_bpm`는 같은 요청 구간의 스칼라 참조다. 연속 워치·PPG와 동기화 이벤트는 [수집 규격](experiment-protocol.md#3-보관-규격)의 별도 시계열 테이블을 사용한다. |

방법과 후보 사이에서 분석 구간이 달라지면 같은 구간의 기준값을 다시 구하거나 해당 쌍을 비교 불가로 표시한다. 시도 행, 실제 관측·보간 마스크, 결과 사용 여부를 보존한다. 기존 MATLAB 호출을 깨는 변경은 팀 합의 후 적용한다.

## 4. 처리·예외 정책

- ROI 일부 손실은 Adaptive Masking으로 유효 피부만 사용하고 전체 손실은 Invalid Marking으로 기록한다. 추적 신뢰도와 SQI를 분리한다. 픽셀 수는 진단에 사용하며 비어 있지 않은 ROI를 임의 픽셀 컷으로 제외하지 않는다. Fixed ROI는 초기 기준이며 최종 평가에는 동일 피부 영역 추적이 필요하다.
- 포화 비율을 기록하고 원본을 복원하지 않는다. Raw와 Hard Masking을 우선 비교한다. Soft Weighting과 Temporal Masking은 후속 비교 후보다.
- 실제 프레임 간격을 사용한다. 정상 시간축을 보존하고 불균일한 구간의 재표본화는 관측 범위 내에서만 처리한다. 짧은 관측 공백의 보간과 구간 분리는 비교가 필요하다. 긴 공백 및 부족한 구간은 결측·실패로 남기며 영상 ROI 패딩과 과거값 채움은 적용 범위를 구분한다.
- 평탄, NaN/Inf, 대역 에너지 0, 참조 누락을 각각 추적한다. SQI 후보와 판정값은 실험 전 등록하며, GT와 상관을 조사하더라도 실사용의 타당성 판정은 신호 정보로만 수행한다.
- 실시간 상태는 High·Moderate 새 BPM, Low 새 측정 보류, Invalid 측정 불가다. 허용한 일시 손실 구간에서는 이전 값의 측정 시각과 갱신 중단 상태를 표시하고 신규 유효률에 넣지 않는다. 각 출력에서 출력 시각 이후의 입력을 참조하지 않으며 BPM을 예측하지 않는다.
- 다중 인원에서는 ID별 ROI·원본 신호·BPM·SQI·상태를 분리한다. ID가 불확실하면 기존 버퍼에 추가하지 않는다. 필수 단일 인원 검증 후 확장한다.

## 5. 데이터·선정·통과 기준

공개 개발 → 피험자 비중복 공개 독립 검증 → 자체 예비 장비 점검 → 설정 고정 → 자체 본 실험 순이다. 자체 최종 시도는 튜닝에 사용하지 않는다. 각 비교는 피험자·영상·창·ROI·고정 설정·후보·성공/실패·후보 탈락 사유·커밋을 기록한다. 정확도, 일관성, 변화 추적, 유효성·지연을 고려하고 연산 비용은 측정 기록에 남긴다.

MAE/RMSE는 신규 유효 추정과 동일 구간 참조가 모두 있는 쌍에서 계산한다. 유효률은 전체 시도, 허용 오차 이내 비율은 참조가 있는 전체 시도(추정 실패 포함)를 분모로 보고한다. Bias·Error SD·ΔBPM·방향 일치·변화 감지 지연에 필요한 공통 시계와 시도 수를 별도로 공개한다. 후보 최고 점수만으로 통과를 선언하지 않고 사전에 정의한 최소 조건을 적용한다. 목표 기반 정규화와 세부 컷은 독립 검증 전에 고정한다. 검토서의 25/25/30/15/5/0은 전체 시스템의 제안 가중치로, 기술별 검증 결과나 확정 수치로 취급하지 않는다.

| 의존 순서 | 구현·비교 목표 | 평가 및 통과 조건 |
|---|---|---|
| 1. 기반 | 비대화형 ROI 입력, 원본 RGB/시각 보존, 고정 ROI A 및 I/O | 1.25 Hz 합성 신호·영상에서 75±1 BPM. 평탄·결측·대역 밖 입력에 실패 코드. 파일 디코딩부터 추정까지 재현 가능해야 한다. |
| 2. 데이터와 실행기 | UBFC-rPPG 등 공식 공개 자료의 영상·PPG·BPM·시간 입력 연결, 개발·검증 분할, 비대화형 시도 실행 | 시도·피험자·구간 연결, 실패와 참조 누락의 보존, 원본 기록 재현, 중복 없는 분할 검사. 실데이터 점검은 측정 조건이 확인된 참가자에 한정한다. |
| 3. 공통 최적화 | Fixed·KLT·NCC·CAMShift·STAPLE·MediaPipe, 시간 필터, FFT 구간/길이, Rectangular/Hann/Hamming, 피크 위치 보간 순서로 비교 | 동일 표본에서 MAE/RMSE·유효률·ROI 안정·지연을 기록한다. 단계별 최소 유효률·실질 차이·동점 규칙을 개발 실험 전에 확정한다. 통과 조건을 충족한 후보만 다음 순서에 반영한다. |
| 4. 방법 비교 | B, C, POS 창, SQI, ROI Fusion을 독립 비교한 뒤 상호작용이 큰 조합을 재검증 | 기본 A 또는 pooled POS 대비 오차·유효률·추세·실패 조건을 기록한다. 완전한 관측·부분 손실을 구분한다. 최종 후보는 개발 게이트 통과와 별도 피험자 검증을 충족해야 한다. |
| 5. 고정과 최종 | 공개 독립 자료와 자체 예비에서 조건을 점검하고 설정·커밋을 고정한 뒤 54개 및 추가 평가를 실행 | 과제의 여섯 거리와 동일 구간 스마트워치 기록, 방법별 그래프와 실패 행, 범위별 지표가 필요하다. 트렌드·거리의 수용 임계값은 연속 기준 장비 검증 후 사전 등록한다. |
| 6. 확장 | 슬라이딩 창 6종 × 갱신 5종, Confidence Decay 비교, ID별 버퍼 순서로 확장 | 미래 입력 변경에 과거 출력 불변, 유지값을 신규 추정으로 집계하지 않음, 교차·가림 시 잘못된 ID에 샘플 혼입 기록. 신뢰성 통과 후보 중 가장 짧은 갱신 주기를 채택한다. |

관련 연구와 강의 페이지, 후보 라이선스 및 툴박스는 [문헌·강의 검토](literature-review.md)에 연결한다. 공개 데이터의 접근·형식·실측 결과와 현장 하드웨어 검증 결과를 분리해 기록한다.
