# 평가 시나리오 수립

상태: 팀 협의용 초안(PROPOSAL). 실제 성능 측정 결과가 아님.
기준: 교수님 과제 안내, 제안발표, matlab-framework 및 feat/signal 개발 문서.

## 1. 평가 목적
- 조원별 구현 코드의 성능 비교 및 최종 코드 선정
- Method A~D의 심박 추정 정확도 비교
- 촬영 거리별 성능 및 한계 분석
- 조명과 움직임에 따른 안정성 검증

## 2. 공통 실험 조건
| 항목 | 조건 |
|---|---|
| 장비 | 스마트폰 후면 RGB 카메라, 삼각대, 스마트워치 |
| 영상 | 1920×1080, 30 fps, 60초 |
| 인원 | 3명 |
| 거리 | 0.5, 1, 2, 3, 4, 5 m |
| 반복 | 거리별 3회 |
| 배율 | 1배 고정 |
| ROI | 이마, 왼쪽 볼, 오른쪽 볼 |
| 심박 대역 | 0.7~3.0 Hz (42~180 BPM) |
| GT | 영상과 동일한 시간 구간의 스마트워치 평균 HR |

기본 실험은 정면 응시, 일정한 조명, 동일 렌즈 및 배율을 유지한다. 거리는 렌즈부터 얼굴까지 측정한다. 실제 프레임 시각, 노출 설정, 스마트워치 기종·기록 주기·갱신 지연을 기록한다. 스마트워치 HR 비교는 ECG 파형 검증이 아니다.

## 3. 세부 평가 시나리오
### S1. 예비 실험
1m, 3명, 2회씩 총 6개 영상. 얼굴 검출, ROI 추적, RGB 시계열, BPF, FFT 및 BPM 출력을 확인한다. 인공 신호 1.25 Hz에서 75 BPM이 나오는지, 대역 외 잡음 및 결측 처리도 검증한다. 예비 영상으로 설정과 실패 판정 기준을 결정한다.

### S2. 조원별 코드 비교
0.5m, 3m, 5m에서 3명, 1회씩 총 9개 영상. 동일 영상과 GT, 하드웨어에서 MAE, RMSE, 유효 추정률, 처리시간을 비교하여 최종 코드를 선정한다. 시스템 비교에는 각자의 ROI 추적 방식도 포함할 수 있다. 선정 영상은 본 실험 영상과 분리한다.

### S3. 영상처리 방법별 평가
| 방법 | 처리 |
|---|---|
| A | Green 평균 + BPF + FFT |
| B | RGB 채널별 3×3 Median Filter + A |
| C | G/(R+G+B) 정규화 + BPF + FFT |
| D | ROI별 POS + 품질 기반 BPM 가중 결합 |

A~D는 동일 영상, ROI 집합, 유효 시간 구간, 타임스탬프 처리 및 심박 대역을 사용한다. B와 C는 A에 각각 독립적으로 적용한다. 공통 ROI의 기본 POS와 개선 POS도 비교하며, 가능하면 ROI별 POS 단순 평균도 추가한다. 개선 효과는 실험으로 확인한다.

### S4. 거리별 평가
| 거리(m) | 인원 | 반복 | 영상 수 |
|---|---:|---:|---:|
| 0.5 | 3 | 3 | 9 |
| 1 | 3 | 3 | 9 |
| 2 | 3 | 3 | 9 |
| 3 | 3 | 3 | 9 |
| 4 | 3 | 3 | 9 |
| 5 | 3 | 3 | 9 |
| 합계 | | | 54 |

54개 영상에 A~D를 적용하여 216회 추정한다. 거리별 ROI 픽셀 수, 추적 실패, 신호 품질, 심박 추정 오차를 분석한다. S3와 POS 비교에 동일 영상을 재사용한다.

### S5. 조명 변화 평가(추가)
1m, 3명, 조건별 2회. 일반 조명(본 실험 재사용), 저조도, 추가 조명, 촬영 30초 시점 조명 변경. 신규 18개 영상. 특히 A와 C의 오차를 비교한다. 가능한 경우 조도를 기록하고, 아니면 조명 위치 및 점등 상태를 기록한다.

### S6. 움직임 평가(추가)
1m, 3명, 조건별 2회. 정면 응시(본 실험 재사용), 가벼운 좌우 얼굴 회전, 대화. 신규 12개 영상. ROI 추적 안정성, 추정 오차 및 실패율을 비교한다.

## 4. 평가 지표
- MAE = sum(abs(HR_est - HR_GT))/N
- RMSE = sqrt(sum((HR_est - HR_GT)^2)/N)
- 유효 추정률(%) = 유효 추정 시도 수 / 전체 시도 수 × 100
- 5 BPM 이내 정확도(추가 제안): GT가 있는 전체 시도 중 절대오차 5 BPM 이하의 비율. 추정 실패도 분모에 포함하며 GT 누락은 별도 보고한다.
- 추가 지표: ROI 추적 성공률, 처리시간, 신호 품질, ROI 픽셀 수.

MAE와 RMSE는 유효 예측과 GT가 있는 영상에서 계산하고 N을 표시한다. 실패 행은 유지하며 원인 및 횟수를 기록한다. 공통 유효 영상의 오차도 비교한다. 코드 선정 우선순위는 5 BPM 이내 정확도, MAE, 유효 추정률, RMSE, 처리시간 순으로 제안한다. 팀 합의 후 고정하며 의료기기 인증 기준은 아니다.

## 5. 실패 판정 기준(초안)
- 얼굴 검출 및 ROI 유지 실패
- 유효 ROI 프레임 비율 90% 미만
- 1초 초과 연속 ROI 결측
- RGB 시계열 부족 또는 유효하지 않은 값 발생
- 유효 FFT 피크 검출 실패
- BPM 출력 실패 또는 설정 범위 이탈

90% 및 1초 기준은 예비 실험 후 확정한다. GT 누락과 추정 실패를 구분한다. 오차가 크다는 이유만으로 실패 처리하지 않으며 GT를 이용해 FFT 피크를 선택하지 않는다.

## 6. 결과물
- 원본 RGB 시계열, 처리 후 파형, FFT 스펙트럼
- 조원별 코드 성능 비교
- 방법별·거리별 MAE, RMSE 및 유효 추정률
- 기본 POS와 품질 가중 POS 비교
- 실패 원인 분석

기존 configs/experiments_template.csv와 MATLAB 함수 입출력 계약을 유지한다. 예측 결과는 video_id, method, predicted_bpm, status, failure_reason을 기록한다.

## 9. 평가 순서
예비 촬영 → 코드 검증 → 조원별 비교 → 최종 코드 선정 → 설정과 판정 기준 고정 → 거리별 본 실험 → A~D 비교 → 성능 평가 및 실패 원인 분석.

본 실험 전 코드 커밋 및 설정을 고정한다. 본 실험 결과를 보고 수정한 분석은 탐색적 분석으로 구분한다. 참가자 동의와 데이터 접근 제한을 적용하며 원본 얼굴 영상이나 개인별 심박·GT를 공개 저장소에 올리지 않는다.

## 10. 팀 협의 사항
예비·선정 영상 수, 추가 실험 범위, GT 시간 정렬 방식, ROI 및 품질 임계값, 코드 선정 기준. 기존 공통 파일은 변경하지 않는다.
